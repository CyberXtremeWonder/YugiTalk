# 用户直接归属与多知识库

2026-10-13按用户要求完全移除工作空间及成员管理，不再创建个人空间。用户登录后直接管理本人Agent、Skill、Tool、知识库、文件、会话、任务与记忆；平台管理员继续保留账号、审计与工具审核权限。

列表与创建接口改为 `/api/v1/me/agents`、`/me/skills`、`/me/tools`、`/me/knowledge-bases`、`/me/conversations`、`/me/runs` 和 `/me/memories`。账户范围由会话推导，所有资源ID读取和修改再次校验账号归属。旧 `/workspaces` 与成员接口不再提供。

知识库可创建多个，每个库仍支持多个文件、文件夹批量上传、进度和失败定位。每库有效文件上限200，每文件上传大小限制保持原有20MB；不是限制只能创建一个库。文件和引用来源仅对所属用户可用。

## 迁移

迁移版本0015：业务表 `workspace_id` 改为 `account_id`，直接外键关联users；删除workspaces、memberships表。共享Agent、知识库、文档与Skill归原唯一所有者，个人对话、任务、记忆与工具保留原用户归属。多个旧空间的数据合并到账号，名称冲突或多所有者时拒绝迁移，不覆盖资源。记忆偏好合并时任一旧设置关闭则继续关闭。原文对象路径与Milvus已有向量保留，不重新下载BGE-M3、不清空索引。

Milvus召回根据关系库授权后的知识库、文档ID和索引版本过滤，随后再次校验SQL资料状态和归属，以兼容旧向量里的历史空间字段。新索引写入用户account_id。历史空间字段不再作为授权依据。

已移除功能对应源文件与旧空间权限用例归档于 `deploy/archive/removed-workspace`，不参与业务应用与自动测试加载。用户自行编辑的 `backend/tests/test_rag.py` 尚有不完整语句，完整回归显式排除该草稿，其余功能执行回归。

数据库变更不能无损自动降级；上线前保存关系库备份与上一版本镜像。独立PostgreSQL迁移测试不修改业务资料，不作为远端恢复演练完成证明。实际迁移结果和备份路径记录在 `docs/stages/artifacts/user-ownership-validation.json`。
