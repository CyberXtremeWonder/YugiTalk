# 邮箱注册、管理员开发模式与个人工具审核

管理员登录后始终显示“管理员面板”入口；即使登录时未勾选开发模式，点击入口也可通过带CSRF的 `/auth/development-mode` 请求显式开启当前会话。后端再次检查平台管理员身份并记录审计，普通用户不能调用。成员请求网络失败时显示中文网络/隧道提示，并提供重新加载按钮；该提示不代表服务端业务错误，也不能替代实际修复隧道断线。

## 邮箱注册

2026-10-12按用户要求，获取验证码时发现邮箱已注册，立即提示“该邮箱已注册”，不发送邮件。已清理7个旧账号及其个人记录，只保留 `cxwAdmin`；知识库、上传资料和工作空间保留并交给管理员，关系库备份见 `data/backups/users-before-cleanup-20261012T045949Z.dump`。

登录页新增注册入口。填写邮箱、显示名称、密码和六位邮箱验证码，验证成功后创建普通账号及个人工作空间，再登录使用。邮箱去除首尾空白并统一小写，数据库唯一索引防止大小写和并发重复注册。普通注册不能设置管理员角色或独立登录用户名，密码仍按用户要求不限制长度，但不能为空。

验证码10分钟有效，60秒内不能重发，最多猜错5次；重新发放后使用新的验证码。数据库只保存绑定邮箱的HMAC摘要。验证码消费、用户与成员关系创建在同一事务提交；SMTP失败不会保留可使用的本次验证码。来源校验和Redis共享限流均在服务端执行。

在私有 `.env` 或 `.env.production` 填写：

```dotenv
REGISTRATION_ENABLED=true
SMTP_HOST=填写服务商SMTP主机
SMTP_PORT=465
SMTP_TLS=ssl
SMTP_USERNAME=填写发信账号
SMTP_PASSWORD=填写邮件服务授权码
SMTP_SENDER=填写允许的发信邮箱
```

587端口通常使用 `SMTP_TLS=starttls`，具体按服务商要求填写。两种方式都验证TLS证书。凭证只放私有文件，不发聊天、不提交源码。修改后重建 `api worker scheduler`，本机热更新API也需重启。

用户暂无SMTP，本轮仅准备配置并使用内存邮件替身验收。业务页面明确提示邮件服务未配置，不返回验证码或假发送成功；测试验证码读取路由只存在于独立fixture，不注册到业务应用。真实邮件送达待配置后验收。

## 管理员与开发模式

管理员用户名为用户指定的 `cxwAdmin`，登录不区分大小写。密码按用户提供的值初始化，源码和文档不保存明文，数据库保存Argon2摘要。管理员内部邮箱 `cxwadmin@admin.invalid` 只作为初始化身份，不用于收信。

登录时勾选“开发模式（仅管理员）”，全部既有功能继续保留，并增加管理员面板：运行环境与依赖状态、分页账号列表、普通账号启停、审计元数据和工具提交审核。停用账号会撤销登录会话；管理员账号不能在启停面板停用。

模式保存在服务端会话，刷新后保留；普通用户不能通过勾选模式提权，管理员角色撤销后接口拒绝。开发模式不切换APP_ENV、不关闭HTTPS/CSRF、不打开生产DEBUG，也不授予其他用户个人工具的使用权。

在另一台新环境交互初始化管理员：

```powershell
docker compose exec api python -m app.identity.bootstrap --email cxwadmin@admin.invalid --name cxwAdmin --platform-admin --username cxwAdmin
```

交互输入密码；重复初始化不重置已有账号，不自动将固定开发密码种入生产。

## 个人工具提交审核

用户在Tool页点击“提交工具审核”，填写只读HTTPS声明。每人每空间最多20项待审提交；不填写真实密钥。普通用户即使是个人空间所有者，也不能绕过审核直接创建或发布工具。

待审声明不进入调用目录。开发模式管理员可批准或填写意见驳回；批准时重新验证声明哈希、提交者启用状态、空间成员关系、名称和目录配额。重复审核被拒绝，审核与版本创建在同一事务提交。

**用户工具绑定提交者，不是公共工具。** 批准后所有者字段记录提交者，同空间其他用户也不能在普通目录查看、维护或调用；管理员审核不会将它公开。目录、Agent/Skill发布、快照冻结、缓存复用、执行和恢复均校验所有者。

本人可启停或删除个人工具，原工作空间的成员边界继续生效；当前名称在空间内唯一。提交入口仅支持新工具，不能原地修改待审声明。批准不自动授权助手/技能，也不代表密钥和域名白名单已配置。默认内置工具及管理员维护的空间工具保留原范围。
