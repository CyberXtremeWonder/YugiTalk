# 运行与错误监控

各模块通过公共入口记录诊断信息：登录与账号、助手、会话、任务、知识库、记忆、技能、工具、审计和健康检查均覆盖 API 请求状态与耗时。这里只记录运行与错误监控，不统计页面访问或按钮点击。

## 查看记录

- Trace：平台管理员在“实时监控”下方进入“Trace”（`#trace`）。任务列表和活动任务明细每 3 秒更新，可暂停、手动刷新及加载历史任务。按执行批次展开模型循环、请求、工具、Memory 读取和现有 RAG 阶段，右侧显示实际耗时条。接口为 `/api/v1/admin/traces` 与 `/api/v1/admin/traces/{run_id}`，逐次校验管理员身份。
- Trace 口径：步骤在独立的 `trace_steps` 表开始时写入、结束时更新，不受 OTel 采样或聊天事件保留期影响。模型请求包含实际重试与 RAG 规划、评判、改写调用；输入 token 沿用供应商解析口径，包括 Anthropic 缓存输入。用量缺失时显示已知部分和未知请求数，任务完整用量保持未知，不用保守额度填补。工具结果复用单独计数；Memory 记录现有数据库读取次数和返回条数，不新增语义检索。执行跨度包含任务恢复前的等待时间，不能与各步骤耗时相加。费用尚未配置。
- Trace 历史与部署：升级到迁移 `0016_task_traces` 后的新执行才产生完整步骤，历史任务不补造记录。删除会话同时删除关联 Trace。记录不包含问题正文、模型正文、记忆正文、工具参数或结果。未正常结束的步骤在租约失效或任务恢复后显示中断。
- 实时面板：平台管理员登录后从侧栏进入“实时监控”（`#monitoring`），每 5 秒刷新，支持暂停、手动刷新、异常类型筛选与关联标识展开。无需开启开发模式。后端 `/api/v1/admin/monitoring` 逐次验证管理员会话，普通用户无法访问。
- 面板口径：Token 和任务为全平台数据库聚合；Token 趋势按任务结束时间展示结算量，执行中增量尚未计入。接口为当前 API 进程最近 15 个分钟桶，重启后重新开始，多进程数据不自动合并；接口排行最多 20 项。面板及指标抓取请求不计入面板接口流量。
- 面板异常：接口保留最近 20 条 4xx/5xx；任务展示窗口内最近 10 条失败记录；资料展示当前失败状态中最近创建的 10 项。没有采集浏览器异常到服务端。模型用量展示累计结算前 8 项。

- 前端：浏览器开发者工具的 Console 中筛选 `[YugiTalk]`。成功请求为 Debug 级别，业务错误为 Warning，网络和服务异常为 Error；需要查看成功记录时开启 Debug/Verbose。前端记录目前保存在浏览器控制台，没有新增远程上报服务。
- 后端：API、Worker、Scheduler 输出到标准日志，可按 `request_id`、`trace_id`、`operation`、`error_code` 查找。启动及查看容器日志的方式见 [启动与监控](START_AND_MONITOR.md)。
- 嵌入服务：独立记录 `embedding_request`、`embedding_failure`、请求编号与耗时。
- 指标：`/internal/metrics` 沿用独立 Bearer 运维令牌保护，输出请求数、状态码、响应头耗时和已有任务、额度指标。意外 500 响应也纳入计数；流式正文耗时不等同于响应头耗时。
- 追踪：沿用 `OTEL_EXPORTER_OTLP_ENDPOINT` 与 `OTEL_SAMPLE_RATIO` 配置。知识库索引、清理任务继承投递请求的追踪标识；模型和工具已有子步骤追踪。未配置导出地址时不向外发送追踪。

## 错误定位

API 返回已有统一错误码和 `X-Request-ID`、`X-Trace-ID` 响应头。前端请求记录保存这两个标识，可据此关联服务端日志。后端未知异常只记录异常类型及最后六个代码位置，不记录异常消息、局部变量或源码行。

前端捕获未处理异步错误和全局运行异常；React 渲染失败时显示重新加载入口。事件流读取失败记录错误类别，并保留原有重连规则。主动取消请求不会记成网络故障。后台任务的 `outcome=returned` 仅表示调用返回，业务结果仍以任务或文档的持久状态和错误码为准。

诊断记录排除密码、令牌、提示词、上传内容、响应正文、查询参数与文件名。前端路径只保留已知资源片段，未知片段统一显示为 `:id`。
