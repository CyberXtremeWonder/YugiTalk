# 按文档类型生成父子分块

上传默认 `chunk_strategy=auto`。先生成完整父块，再在每个父块内切子块，子块数量没有三块限制。新策略检索到一个子块即可取回父块，同一父块多次命中只返回一份；SQL 授权、版本与父子关系校验继续执行。

| 类型 / API 值 | 父块上限 | 子块上限 |
| --- | --- | --- |
| 通用短文档 / `short` | 500 字符 | 100 字符 |
| 长文档 / `long` | 1000 字符 | 200 字符 |
| Token 计量 / `tokens` | 1024 tokens | 256 tokens |
| 结构化文档 / `structured` | 章节或完整条目，最长 2048 tokens | 子条目或完整句子，过长时按 256 tokens 继续切分 |
| 超长文档 / `ultra` | 4096 tokens | 400 tokens |

长度是上限，短内容不补齐。父块之间不重叠；固定大小子块保留 10% 重叠（按最近整数取整）。结构化文档的完整句子或子条目各自成块，不人为重复相邻句子，只有超长句子继续切分时使用 10% 重叠。普通分块也优先选择接近上限的段落或句末，不把已经完整的短段落强行拆散。父块不跨页，保留可识别的章节边界。所有子块额外受现有 embedding 输入 2000 字符上限约束。

## 自动识别

在提取后的文本上使用确定性规则，不调用生成模型：

1. 至少两个 Markdown 标题、`【条目】`、`第X章/节`，或至少三个数字/中文数字编号条目，采用结构化方案。Markdown 三反引号代码示例不参与这一判断。
2. 否则，文本达到 20,000 字符采用超长方案。
3. 否则，超过 2,000 字符采用长文方案；若 ASCII 英文字母超过文本长度的一半，则采用 token 方案。
4. 其余采用通用短文方案。

这是结构、长度与语言的启发式选择，不是医学文档分类器，也不保证能识别所有标题格式。上传界面的“文档分块类型”允许覆盖规则，批量上传时对本批全部文件生效。文件列表显示实际识别结果；已有资料可以选择“重新分块”类型，再点击“重新索引”。

## Tokenizer 与部署

Token 计数使用本地 BGE-M3 的真实 `tokenizer.json`，上限包括模型特殊 token；不会下载模型，也不会在缺少 tokenizer 时改用字符估算。`BGE_MODEL_PATH` 可指向 tokenizer.json、本地模型目录，或包含 `snapshots/<EMBEDDING_REVISION>/tokenizer.json` 的 Hugging Face 缓存目录。相对路径以项目根目录为基准。

开发及生产 Compose 将 `BGE_MODEL_PATH` 对应目录只读挂载给后端。后台仅加载 tokenizer，不加载模型权重。远程使用 BGE-M3 嵌入时，也需在后端提供相同修订的 tokenizer 文件；其他 embedding 模型当前不能使用三种 token 方案，会返回 `chunk_tokenizer_model_mismatch`。缺少或损坏 tokenizer 返回 `chunk_tokenizer_unavailable`。

更新依赖及容器后生效。短文、长文字符方案不需要 tokenizer。普通文档单文件上传上限为 20 MB，提取文本最多 500 万字符、PDF 最多 2000 页、最多 6 万个子块。Docling 响应与解析进程输出分别最多 128 MB；Linux 解析进程内存为 1 GiB、CPU 时间为 120 秒，文本解析墙钟时限为 150 秒。Docling 转换窗口仍为 600 秒，独立解析进程时限为 650 秒。索引继续每批处理 16 块，超大文件可按需调整 `DOCUMENT_INDEX_TIMEOUT_SECONDS`（默认 1800 秒，最大 7200 秒）。更新 API、Worker、Docling 和前端后，对失败文件点击重试即可；超过新资源上限仍需拆分。

## 兼容性与效果边界

原有 `fixed`、`markdown_sections` API 策略及旧资料的三子一父关系继续兼容；已有资料不会自动重建。新策略的请求类型和识别结果写入 `chunk_strategy`，重试保留请求方式，自动模式会重新识别；更换规则会增加索引版本并完整重新解析、嵌入和索引。同一文件重复上传不同策略会报冲突，应在现有文件上重新索引。

最终检索仍受既有 Top5 和 5000 字符上下文预算限制，所以取回父块不等于父块一定完整进入最终回答。已重跑同一 MIRACL 中文 dev 的 393 题对照，结果见 [父子分块质量复测](evaluation/CHUNK_PROFILES.md)。本批全部识别为结构化文档，新自动方案 Recall@5 为 61.41%，旧章节方案为 64.91%；本轮没有取得质量提升证据，不能把之前的 token 大小实验分数视为本次实现的结果。

## PDF 加密处理

带加密标记但无需输入打开密码的 PDF，先用空密码解密，在内存中生成未加密副本后交给 Docling；对象存储中的上传原文件保持不变。确实需要打开密码时返回 `pdf_password_required`，超过 2000 页时返回 `pdf_too_many_pages`，不再将这两种原因合并提示。

## JSONL 与 Excel

支持 UTF-8 `.jsonl`，单文件最多 5 GB（5 × 1024³ 字节），每个非空行必须是一条完整 JSON 值；允许 BOM 与空行，保留嵌套字段，将转义的 Unicode 转为可检索字符。每条记录单独建立分块边界，不跨记录组合父块；长记录仍按所选方案切分。任一行无效则整份导入失败，返回 `invalid_jsonl`。单文件上传与文件夹导入均支持 JSONL。Excel 使用 `.xls`、`.xlsx` 扩展名，沿用 Docling 提取工作表、列名和行号的解析方式。

大型 JSONL 上传时只保留 1 MB 内存缓冲，临时文件写入独立磁盘卷 `document_uploads`，随后执行 S3 分段上传；该卷需为每个并发上传预留至少文件大小的可用空间，不能替换成内存 tmpfs。代理最大请求体为 5g，关闭请求缓冲。其他文件类型仍最多 20 MB。

JSONL 不再套用普通文档的全文件字符数和分块数限制，而是逐条解析，每条记录最多 20 MB、提取文本最多 500 万字符、最多 6 万个子块。相邻记录合并至至少 128 个子块或 128 行后处理，父块仍不跨记录；Embedding 请求保持每次最多 16 块，向量写入扩大至每次最多 128 块，SQL 子块使用批量插入，减少网络请求和事务提交。每次模型请求前仍校验租约，向量写入持有文档锁；约每分钟完成当前记录组后保存字节位置、记录数及分块数，再排队继续同一索引版本。所有记录成功前不会发布为可检索资料；格式错误时已写入的中间结果仍不可检索。显式重试会建立新版本并从头处理，非正常 Worker 丢失仍沿用已有版本隔离恢复策略。前端显示已处理字节、记录数和分块数；原文件下载也采用流式传输。

删除失败的资料保持不可检索，调度器自动重试。Milvus 返回集合恢复中（106）时，首代 JSONL 可根据已提交父块的子块总数生成确定性主键，分批删除向量并保存清理检查点，覆盖向量已写入但子块 SQL 未提交的情况；不删除共享集合。多代索引保留原有按文档过滤清理方式，避免漏掉历史代数中的向量。Windows 一键启动会检查已有 CUDA 镜像是否可用并保留 GPU 配置；首次安装 CUDA 镜像使用 `scripts/start-local-embedding.ps1`。

部署需先运行数据库迁移 `0022_large_document_size`，将 `documents.size` 扩展为 64 位整数，再更新 API、Worker、前端与反向代理。正式站点使用实际部署的 Nginx 配置，不能只更新仓库文件。


## 导入错误与重试

### 独立索引时限

文档索引使用 `document_index_timeout_seconds`，默认 1800 秒，可配置 60 至 7200 秒；Celery 索引任务软时限使用该值，硬时限再增加 10 秒。普通对话和单次嵌入请求分别受自己的限制，不能通过增加索引时限修复所有超时。

旧问题记录中，732 个分块的 PDF 曾在第 272 块触及 300 秒软时限。该例用于解释为何分离索引时限，不是当前性能基准。修改 `DOCUMENT_INDEX_TIMEOUT_SECONDS` 后需要 Worker 重新加载配置；失败文件通过重试入口建立新索引版本并从原文重建，不是逐块断点续算。

### PDF NUL 与错误分层

PDF 字体映射可能提取出 NUL 字符。`rag/parser.py` 在 PDF 文本分块前清理 NUL，保留原 PDF；TXT 和 Markdown 保持各自非法文本校验。分块写入 PostgreSQL 的错误使用 `document_chunk_storage_failed`，不能统一归类为 Milvus、向量维度或模型服务故障。

历史案例中的 PDF 曾生成 128 个分块并包含 5 个 NUL，实际失败在分块入库，嵌入尚未开始。重试后曾完成该文件索引；这一历史结果不等于所有 PDF 均通过。诊断应先区分解析、分块入库、嵌入、向量写入和总执行时限，再决定调整资源或拆分文件。
