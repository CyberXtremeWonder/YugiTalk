# 对话中的研究与文件交付

用户直接在普通对话中提出研究目标、资料范围及文件格式，助手按需要调用研究与文件工具，最后在原对话回复下提供下载附件。没有独立研究导航，也没有模式开关。

**单纯生成文件不等于开展研究。** 已有完整内容时，“我要 PDF”“把刚才内容转成 Word”等导出请求只开放 `export_document` 排版工具，不额外检索。前面已经提出研究目标但尚未交付时，“报告要 PDF”是对原任务新增格式约束，保留研究能力，并同时使用此前主题、时间范围、篇幅和风格要求。成功返回一段拒答不等于研究已完成。先前失败任务留下的半截答复不会被选作导出正文；没有正文也没有待完成目标时才请用户补充。

例如：“研究这两种方案的部署限制，引用原始资料，生成 Word 和 PDF。”或“只根据下面的材料整理报告，不联网，给我 Markdown 文件。”支持 `.docx`、`.pdf`、`.md`；未指定格式时工具默认 Markdown。文件由服务端实际生成并持久保存，模型不能伪造下载链接。普通咨询无需生成文件。

## 启动

1. 按项目部署流程先备份数据库，再应用 `0023_research` 迁移。本机在 `backend` 目录执行 `.venv/Scripts/python.exe -m alembic upgrade head`，Docker 可执行 `docker compose run --rm migrate`。
2. 更新依赖并重新构建 API、worker、scheduler 和前端。运行依赖新增 `python-docx`、`reportlab`，容器增加文泉驿中文字体用于 PDF 嵌入。
3. 选择配置好模型的已发布助手，直接开始对话。网页研究需要助手允许 `web_search`，服务端配置 `TAVILY_API_KEY`，并在 `TOOL_HTTP_ALLOWED_HOSTS` 中允许 `api.tavily.com`。没有外网工具时可根据用户提供的文字或授权知识库生成文件。

Mock 可以验证自然语言请求、文件生成和下载，但输出明确说明未执行真实研究，不能作为实际模型质量的证明。本轮未对正在运行的业务数据库执行迁移或部署。

## 对话流程

普通 `/runs` 提交接口保持不变，前端不提交模式参数、输出格式参数或研究项目 ID。直接生成文件使用 `export_document`；明确要求补充研究时才使用 `research_report`。平台创建仅供执行恢复和文件保存的内部记录，用户不需要管理它。

主助手委派时传递已组装的对话上下文，而不是仅依赖最近一句委派文本。研究记录会持久化最近多轮用户原文要求及已有会话摘要，明确后续修改优先；新任务冻结对话序号，避免恢复时将后来的用户输入混入这份研究要求。

研究工具拆解最多四个子问题，每题默认至多两轮检索和覆盖检查，按缺口补查，然后生成带原句引用的报告与指定文件。只整理用户材料时关闭网页检索；用户材料作为单独证据保存。内部知识库仍按当前登录用户过滤。工具只允许三种固定文件格式，不接受用户路径、Shell 或可执行代码。

助手回复附带机器生成的附件列表。刷新和重新打开聊天会重新读取同一批附件；每次下载重新校验会话、所有者及内部来源状态。研究过程中的简短计划和进度在对话中展示，停止操作沿用现有任务取消。

任务记录按用户保留创建时间最近的 100 条，时间相同时用任务 ID 稳定排序。任务页显示对话标题、至多 160 字符的提问摘要和时间；Trace 列表仅对本人任务显示摘要。提交新任务和调度器巡检会清理超出的已结束任务及关联事件、工具执行账本、恢复记录和 Trace。活动任务及短暂收尾中的 Trace 暂不删除，因此数据库可能暂时超过 100 条；任务结束后继续清理。聊天消息、生成文件、文档和已结算的累计用量不随任务记录删除，清理后的旧任务无法再重试。

## 持久化及恢复

对话支持后台执行期间继续发送消息：普通问题创建独立 Run，前端按原始用户消息绑定流式回复、过程和附件。每个活动任务独立监听和刷新恢复，对话中不提供“停止此任务”按钮；同一用户仍受并发上限限制，默认最多 2 个任务。

新任务的历史以提交时的消息序号为截止位置，旧任务不会读取其他并行任务后发的消息或未来摘要。执行期间发送的新消息均创建独立任务，不修改正在执行的任务。

- `research_projects` 保存研究目标、选定资料范围、计划、各轮结果和阶段状态；`research_sources` 保存来源快照；`research_reports` 保存校验后的报告及文件字节、哈希、文件名和 MIME 类型。
- 研究调用通过原 Run 检查点中的命名空间绑定参数指纹和项目 ID。恢复复用已提交模型阶段、来源与文件。不同委派和研究调用不能串用搜索账本。
- 文件保存到报告记录后才向工具调用者返回成功；聊天消息动态关联原 Run 的附件。报告正文不会复制进普通聊天历史，避免副本绕过来源失效检查。
- 任务默认研究时限为 600 秒，原 Token 预算开关仍生效。Agent Worker 外层软超时至少为 1800 秒，硬超时再加 10 秒；普通任务仍按自己的较短 Run 快照时限检查。
- 最多保存 24 份来源，按同 URL 或同内部证据去重，同查询复用。重复或空补查词、补查没有新来源会停止该题并记录原因。
- 研究先继承同一次任务已取得且在选定范围内的知识库证据与网页搜索摘录，逐题评估覆盖程度；证据充分时跳过补查。相同网页查询复用工具账本，知识库查询复用前重算文档版本范围；需要全文时仍可读取已有网页，摘要不会冒充全文。
- 研究结构化请求在 DeepSeek Flash 上关闭思考并使用 JSON 输出；计划、评估最多 6000 输出 Token，报告最多 16000，均不超过 Agent 配置上限。研究的输出截断允许手动恢复，已提交的计划、检索与评估继续复用，不自动重试付费请求。
- 普通 Agent 与研究模型请求共用 `MODEL_CONTEXT_LIMIT_BYTES` 容量保护，默认 131072 UTF-8 字节（128 KiB），包含工具 Schema 和追加的证据指令；这是服务端保护值，不是模型的 Token 窗口。超限明确停止，不静默删去来源。调整容量后可从已提交检查点重试，已完成的工具结果继续复用。
- 中断但尚未提交的模型请求或原文读取可能重发，不能承诺外部严格 exactly-once。

内部研究 API 保留作为执行及兼容接口。`GET /research/runs/{run_id}/progress` 仅返回公开计划和进度；`GET /research/{project_id}/files/{format}` 返回带下载响应头的文件；聊天历史返回附件元数据，不返回文件内容。删除对话不删除研究文件，但没有独立文件管理入口。

## 文件与证据边界

Word 为可编辑的 Letter 纵向文档，含黑色标题、中文正文、引用和页码。PDF 优先嵌入系统中文字体，Docker 使用文泉驿；Markdown 保留原报告及脚注。三种文件来自同一份校验后的报告，不分别调用模型生成不一致的内容。

每条研究发现必须引用本项目证据 ID 和逐字原句，未知 ID 或原句不存在时拒绝发布报告。事实、推断及冲突分别标记；链接与脚注由服务端构建。此校验确认来源和原句存在，不证明原句逻辑上充分支持结论，仍需研究质量评测和人工审阅。

公开网页只读取公共 HTTPS，固定已验证的 DNS 地址并校验 TLS，不带用户凭据、不跟随重定向。每次读取最多 20 秒和 4 MiB；接受 HTML、文本和 PDF。PDF 最多处理 40 页，保存至多 24000 字符正文及截断标记。扫描 PDF 此路径不做 OCR，可先上传到知识库解析。极端复杂 PDF 的单次文本提取仍可能超过读取时间，后续需资源隔离的解析进程。

读取失败时可保留明确标记的搜索摘要，不能当作已读全文。模型每份来源使用前 1000 字符并记录摘录截断，完整快照供服务端核验。作者、发布日期未提供时不猜测。尚未实现转载来源归并、结论语义蕴含验证或可编辑计划。

内部文档删除、换版或权限失效后，聊天附件标记不可下载，下载接口也会拒绝旧文件。已下载到用户电脑的副本无法撤回。

## 验证

- 后端：`python -m pytest tests/test_conversation_files.py tests/test_research.py tests/test_agents.py tests/test_subagents.py tests/test_reliability.py -q`。
- 前端：`npm run typecheck`、`npm test`、`npm run build`。
- 浏览器：根目录 `node scripts/check-research-ui.mjs`，以模拟接口验收普通聊天提交、无模式参数、研究进度、三种附件、下载和刷新恢复，截图在 `frontend/.cache/research-ui/research-ui.png`。
- 文件检查：Word 重新解析正文，PDF 重新解析页数及中文文本；测试同时覆盖下载权限、来源失效和普通对话不生成文件。
- 直接导出：`tests/test_direct_export.py` 验证短 PDF 请求只暴露导出工具、原答复原样入文件、跳过失败片段、无正文时澄清；检索/网页/研究入口都替换为失败断言，确认没有调用。即使模型提出知识库调用，也会在执行前拒绝。

本轮后端相关回归 73 项通过，另新增“模型不得伪造用户原始资料”回归并单独验证通过；前端 64 项通过，类型检查、涉及代码的 Ruff/Mypy 和生产构建通过。浏览器六类交互通过且无页面异常。PDF 两页中文样例已渲染检查，Word 已重新解析验证结构和正文；本机缺少 LibreOffice，Word 的逐页渲染复核未完成。容器新增字体与依赖尚未执行镜像构建验证。

模型、网络和浏览器接口测试使用明确的替身，不消费真实研究服务；实际 Tavily、真实模型生成质量和 PostgreSQL 并发恢复尚需部署环境验收。
