## 阶段 0

1. 严格 Schema：合法工具参数通过，未知工具、额外字段、错误类型与空标题被拒绝。
2. SQLite 检查点：审批中断后关闭并重建 saver，分别通过与拒绝，验证终态与线程隔离。
3. 容器集成：真实 Redis 投递至 Linux Worker，PostgreSQL 保存中断状态，下一条任务恢复；验证关系数据库连接与 Worker ping。原 pgvector 距离验证保留在历史报告，当前向量验证改为 Milvus。
4. 重启验证：先提交审批中断，重启 Worker 后恢复同一 thread_id，不依赖内存对象。

6. 静态检查：Ruff lint/format、mypy 严格检查、Compose 配置校验、锁定依赖。

## 验收规则

- 自动化通过和用户验收是两个状态，报告分别记录。
- 无凭证的真实模型联调不得用 Mock 替代；在阶段 3 提供限额内的独立联调方法。
- 不为简单代码或样式凑测试；边界、恢复、安全与关键用户旅程必须验证。
- 默认不调用付费模型、不向真实外部服务写入。

## 阶段6当前验证入口与边界

`pwsh -NoProfile -File scripts/test-stage6.ps1 -IncludeProduction -IncludeRestore -IncludeUI` 检查工程质量、随机独立生产凭证、HTTPS与真实存储、冷备新目录恢复、20并发鉴权查询与HTTPS浏览器。模型协议替身明确标记，不能替代真实模型质量。短时查询不替代本计划规定的30分钟混合任务；完整稳定性、真实模型与安全门槛尚未完成，见 [阶段6报告](./stages/06-production.md)。升级/回滚单独通过固定镜像ID演练，无数据库降级。

完整混合测试入口为 `backend/.venv/Scripts/python.exe scripts/check-stage6-soak.py --seconds 1800`：隔离项目20个用户/空间、共享RAG资料、100份中文合成文档/1000标注检索问题、顺序20次聊天预热，再运行20并发混合聊天/只读工具/RAG/取消/查询和幂等重发。测试用Mock、Worker8进程与明确的测试预算覆盖，不能称为生产默认容量或付费模型测试；记录队列、资源、一致性和配置恢复。`--skip-retrieval`或30秒调试均不能通过完整验收。

负载为20个并行用户，每用户每轮至少间隔5秒，前一操作未完成时不叠加；理论上限约4次操作/秒，持续30分钟通常7200次操作。这里的20并发指用户数量，不代表全程20个请求在途，也没有测最大吞吐。普通接口另用400请求/20线程无等待批量验证。判断性能时必须连同这些节奏、CPU容量和模型类型一起引用，不能把Mock结果推广到真实模型。

2026-10-11补充：API正式覆盖配置为2 CPU；每轮压测在报告内采集实际镜像ID、CPU和内存限额。完整结果保存`stage6-soak.json`，调试单独保存`stage6-soak-debug.json`，重复执行先保留历史；首内容含提交和排队时间，并额外记录提交耗时。阶段脚本可加`-IncludeProduction -IncludeSoak`执行完整压测，或`-IncludeProduction -IncludeSecurity`执行离线全镜像检查；镜像存在高危/严重项时安全检查返回失败。不同资源容量、暖机方法和镜像的结果不可直接当作同等条件优化对比。
