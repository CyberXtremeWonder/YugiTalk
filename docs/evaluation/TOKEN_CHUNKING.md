# 512 / 256 / 128 / 100 token 分块对照（10% 重叠）

2026-10-26。七组各完成 393 题，共 2,751 次问题检索，零失败。

本轮四种 token 方案中，512 tokens 最好，但未优于按章节的 700 字符对照（Recall 差值 -0.29 个百分点，95% 配对区间 [-0.80, +0.19]）。256、128、100 tokens 在当前 Top5、三子一父和严格完整证据口径下逐步下降。建议暂不因本次结果把现有方案改成更小的 token 块；若需要精确控制模型输入长度，512 tokens 是值得保留的候选。

## 测试范围与固定配置

MIRACL 中文 dev 的 3,786 个已标注正负段落，原文打包为 38 份 Markdown；393 个问题、994 条正例标注。不是官方约 493 万段的完整语料评测。此次 dev 用于对照选型，不再将其宣称为未参与选型的独立测试集。

使用本地 BAAI/bge-m3，revision `5617a9f61b028005a4858fdac845db406aefb181`，真实 RTX 4060 Ti GPU FP32 推理。AutoModel + CLS pooling + L2 normalize，与模型的 SentenceTransformer 模块配置一致；max_seq_length=1024。没有调用聊天/生成模型。

独立 Milvus 2.5.14 集合，cosine 稠密检索 + 原生 jieba BM25，每路 Top24，稠密阈值 0.35，RRF 常数 60，融合后最多 24 条；三子一父、合并比例 0.5；最终 Top5、总计 5,000 字符。关闭重排和图谱。相同原文位置及内容使用相同分块 ID，稳定并列排名。

四组 token 方案和 10% 字符对照均保留 Markdown 章节边界，章节内硬切；未额外引入语义或句子切分。token 上限包括 `<s>`、`</s>` 两个特殊 token，正文重叠量按目标上限的 10% 四舍五入。父块原文根据偏移去重，消除 100 字符重叠上限的干扰。

这是使用相同检索规则的隔离组件实验，未走业务上传、SQL 授权和 `/search` 完整接口。未修改生产分块默认值或业务索引。字符基线、父块内容和逐题计分已与项目原实现独立核对。

## 结果

| 方案 | 重叠 | 分块数 | Recall@5 | Hit@5 | 全部正例完整命中 | MRR@5 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 固定 700 字符（原方案） | 100 字符 | 1,350 | 59.09% | 76.59% | 38.42% | 0.6233 |
| 章节 700 字符（原方案） | 100 字符 | 3,817 | 64.92% | 84.48% | 41.22% | 0.6132 |
| 章节 700 字符（10% 对照） | 70 字符 | 3,817 | 65.21% | 84.48% | 41.73% | 0.6117 |
| 章节 512 tokens | 51 tokens | 3,813 | 64.93% | 84.48% | 41.48% | 0.6148 |
| 章节 256 tokens | 26 tokens | 4,125 | 62.50% | 82.95% | 38.93% | 0.6034 |
| 章节 128 tokens | 13 tokens | 6,124 | 54.18% | 76.59% | 32.82% | 0.5193 |
| 章节 100 tokens | 10 tokens | 7,481 | 46.90% | 70.23% | 25.95% | 0.4770 |

Recall@5：逐题计算被完整覆盖的正例比例，再取宏平均。Hit@5：至少完整覆盖一条正例的问题比例。全部正例完整命中：一题的所有正例均被完整覆盖。每条标注引文必须完整出现在同一条返回来源里，忽略空白及大小写；跨来源拼接或只有部分答案不算完整命中。这些指标不等于最终回答正确率。

## 解释边界

- 所有方案均没有触发 embedding 的 1024-token 截断，因此此次差异不能归因于避免模型截断。
- 512 token 是最大长度，短章节不强行填满；这批资料的章节普遍较短，因此它与 700 字符方案有大量完全相同的分块。
- 小块同时缩短了三子一父的父块跨度，可能让整段正例无法完整放进一条证据；实验结论适用于当前 Top5、父块和严格全文覆盖口径。
- 真实向量按相同文本缓存复用，问题检索使用 8 个并发；记录的耗时不可作为不同分块方案端到端延迟的公平对照。
- 分块数近似反映向量条目和索引开销，不等同于实际 token 计费或存储字节。

## 复现与产物

脚本：`scripts/benchmark-token-chunking.py`。独立服务：`outputs/token-chunking-20261026/compose.yml`。以下从仓库根目录执行，Python 需有 CUDA torch、兼容的 transformers/tokenizers、numpy、httpx。

```powershell
docker compose -f outputs/token-chunking-20261026/compose.yml up -d
$env:HF_HUB_OFFLINE='1'
$env:TRANSFORMERS_OFFLINE='1'
python scripts/benchmark-token-chunking.py --dataset outputs/miracl-zh-dev --model E:/Code/HUGGINGFACE_CACHE/models--BAAI--bge-m3/snapshots/5617a9f61b028005a4858fdac845db406aefb181 --output outputs/token-chunking-20261026/final --vector-cache outputs/token-chunking-20261026/vectors
```

最终数据在 `outputs/token-chunking-20261026/final/`：`experiment.json` 固定参数及文件哈希，`summary.json` 汇总，`diagnostics.json` 配对差异，`verification.json` 独立核验，各方案 `*-chunks.json` 和 `*-cases.jsonl` 保存完整分块与逐题来源。根目录和 `overlap10/`、`results10/` 是中断的试运行，不用于最终结论。
