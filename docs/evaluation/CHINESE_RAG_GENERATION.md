## 数据与抽样

来源为 [OpenBMB/RAGEval DragonBall](https://github.com/OpenBMB/RAGEval)，固定 revision `c44aa98aea18362eb5e3751f11e13dbc8f6cab83`。它是作者发布的合成场景文档和问答，不是真实业务资料的抽样。中文部分保留全部 108 篇文档：金融 40、法律 30、医疗 38；英文资料未参与本轮。

固定种子 20261108，每领域选 25 道可回答题及 5 道官方“无关无解”类题，合计 90 题。进一步核对参考答案后，该类型包含 13 道完全无答案题及 2 道部分可回答题；部分可回答题要回答已知部分、拒答未知部分，不能整题拒答。问题清单没有因模型表现调整。事实、跨文档整合、比较、时间顺序、推理及总结类型均有覆盖。

标准引文须能逐字对应到发布文档（忽略空白），无法核验的引文和重复问题在抽样前排除，清单见 `dataset.json`。纯无答案题的原始 `doc_ids` 有 9 条跨领域元数据异常，保留原值作审计；这些 ID 不作为正例相关性标注，也不用于无答案对照的输入。可回答及部分可回答题的来源归属另行核验。

`dataset.json` 中 `unanswerable` 分组沿用官方类型族，需结合 `partial_answerable` 区分部分可回答题；可读回答文件已显示三种答案状态。

## 固定链路

- 原文按 700 字符窗口、100 字符重叠生成 544 个块，保留文档 ID 和原文字符位置。
- 本地 GPU BGE-M3，同一修订、FP32、CLS+L2、1024 维；544 个块和 90 个问题共 634 条真实向量，没有触发 1024-token 截断。
- 小语料采用精确余弦：PostgreSQL/pgvector 距离排序，Milvus FLAT。按领域过滤，Top24 候选取前 5 个块，字符预算上限 5000（本轮最多实际 3500 字符）。没有 BM25、重排、父块展开、图谱或 Agent 工具循环。
- Milvus 在专用实例写入、flush、重新加载已封存段，使用 Session 读取冻结语料。该轮不是大规模 ANN 性能实验。
- 生成和判分均使用项目已配置的 `deepseek-flash`，temperature=0，关闭 thinking，每次最多 1024 输出 tokens。生成提示要求只依据资料、证据不足明确说明，并使用 `[S1]` 引用。

四组输入：

1. `pgvector`：实际检索的五个块。
2. `milvus`：实际检索的五个块。
3. `oracle`：只提供发布的标准引文，不给参考答案。引文有时缺主体或时间背景，因此不作为理想上限。
4. `gold_documents`：提供标签指定的完整相关文档，不给参考答案；完全无答案题给空资料，部分可回答题保留相关文档。该组使用已知标签且不受 RAG 片段预算限制，仅作上下文诊断，不是可部署检索器。

两库在全部 90 题上检索上下文一致。完全相同的完整提示词复用一次真实返回并记录 `reused_from`，避免把生成随机性当成数据库差异。最终有 360 条回答记录，对应 257 个不同完整生成提示词和 257 个不同评分提示词，不能把复用记录当成独立重复采样。

## 回答结果

“判正确”是同模型自动评估与发布参考答案的核心事实是否匹配，允许同义改写；不是全量人工裁决或官方 RAGEval 分数。

| 领域 | pgvector 判正确 | Milvus 判正确 | 仅标准引文 | 完整相关文档 |
| --- | ---: | ---: | ---: | ---: |
| 金融 | 23/30（76.67%） | 23/30（76.67%） | 17/30 | 29/30（96.67%） |
| 法律 | 20/30（66.67%） | 20/30（66.67%） | 22/30 | 27/30（90.00%） |
| 医疗 | 17/30（56.67%） | 17/30（56.67%） | 17/30 | 26/30（86.67%） |
| 合计 | 60/90（66.67%） | 60/90（66.67%） | 56/90（62.22%） | 82/90（91.11%） |

两库这一轮没有产生不同的模型输入，因而没有数据库导致的回答差异；这不是两次独立生成恰好一致的证据。

完整相关文档组比实际 RAG 多匹配 22 题，提示本轮片段选择及上下文完整性值得优先排查。这个差值不是纯粹的“检索错误占比”：对照使用了已知相关文档、不同上下文长度与更少干扰，且生成、判分都有模型误差。

## 文档命中不等于证据完整

以下仅统计每领域 25 道完全可回答题，不混入 13 道完全无答案及 2 道部分可回答题：

| 领域 | Top5 文档 Recall | 完整标准引文覆盖 |
| --- | ---: | ---: |
| 金融 | 100.00% | 81.50% |
| 法律 | 98.00% | 80.33% |
| 医疗 | 94.00% | 62.40% |

文档 Recall 是返回来源覆盖标准文档 ID 的比例；引文覆盖要求同一条完整标准引文出现在同一条、且属于标准文档的返回片段中，忽略空白，不跨块拼接，再取逐题宏平均。它不是语义召回或回答准确率。

示例 `zh-q:5874`：问题要求比较两名虚构患者的血压。实际检索片段没有包含其中一人的 `150/90`，RAG 回答称该病历未记载血压、无法比较；完整相关文档对照则给出 `150/90` 与 `120/80` 并作出比较。原始文档确有该数值，这说明“未检索到”不能直接扩展为“原文没有”。完整回答及证据可逐题核查。

另一个示例 `zh-q:140` 的题目指定了“2017年7月”，发布的标准引文仅明确年度与投资平台；模型对月份提出限定。该类题设与证据粒度问题保留在结果中，没有事后删题以提高分数。

## 判分与质量边界

最终判分严格分开两个维度：`correct` 对照发布参考答案；`fully_supported` 只核查实际提供的片段。检索漏掉证据时，可以“回答未匹配参考答案，但拒答受已给资料支持”，不能误判为参考答案错误。

自动评分把本轮全部回答的证据支持字段判为 true，但不能据此声称“零幻觉”或“事实支持100%”。例如上述病历案例中，把片段缺失表述为整份病历未记载，自动评分仍接受其支持性，说明该指标可能偏乐观。引用 ID 全部有效也只证明编号有效，不证明事实正确。

主要限制：合成小语料、90 题、一次生成、同模型生成与判分、参考答案可能存在粒度或质量问题、没有全量专家裁决。没有评估中文大规模 HNSW、高并发、完整线上 Agent 链路，也没有因此切换项目向量库。

原始 JSONL 数据、标准答案、全部提示词、原始返回、Token 用量、评分理由均保留。抽样分类和评分维度校验修正的过程记录分别存于 `sampling-calibration/`、`grading-calibration/`，不混入正式题目评分。`usage-all-recorded.json` 汇总已记录回执，包含校准及最初探针；取消时未返回的请求、未报告的重试用量不属于已知回执，汇总不是供应商账单，未虚构人民币费用。
