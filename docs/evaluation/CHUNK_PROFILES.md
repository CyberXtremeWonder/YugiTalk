# 新文档类型与父子分块检索质量复测

2026-10-27。四组各完成 393 题，共 1,572 次问题检索，零失败。

本轮新自动方案 Recall@5 为 61.41%，相对旧章节方案 64.91% 下降 3.50 个百分点；配对 95% 区间为 [-7.23, +0.19] 个百分点，跨过零，不能声称统计上明确退化，也没有取得提升证据。新 token 方案为 63.72%，相差 -1.19 个百分点，区间 [-2.57, +0.07] 同样跨零。自动方案的向量条目增至约 3.66 倍，当前结果不支持把它视为质量升级。

## 固定评测条件

同一 MIRACL 中文 dev 的 393 个问题、994 条正例标注、3,786 个已标注正负候选段落，打包为 38 份 Markdown。数据和代码 SHA-256 已记录。范围不是官方约 493 万段完整语料，也不是最终回答准确率评测；这批 dev 已用于对照选型。

本地 BGE-M3（revision 5617a9f61b028005a4858fdac845db406aefb181），RTX 4060 Ti，FP32，CLS pooling + L2 normalize，1024-token 上限。Milvus 2.5.14，cosine Dense + 原生 jieba BM25，每路 Top24，Dense 阈值 0.35，RRF60，融合 Top24；最终 Top5、总计 5000 字符。关闭重排、图谱和生成模型。

本轮直接使用生产 `parse()`、`attach_parents()`、`VectorIndex.recall()`、`rrf()`、`document_scope()`、`materialize()` 和 `pack_evidence()`。每组建立独立 Milvus 集合和隔离 SQL 父子关系，实际执行 SQL 用户/知识库授权、版本及父子关系校验；没有走业务上传及 `/search` 完整 HTTP 接口。相同文档、相同正文和出现次序保持同一子块 UUID，控制并列排名。

四组均按当前代码和本轮索引重新检索，未把上次缓存的旧检索成绩作为当前对照。两次实验的身份生成方式不同，分数的小幅变化不能解释为代码效果变化。相同文本的真实向量按模型配置核验后复用，仅新增文本重算。

## 结果

| 方案 | 子块数 | 父块数 | Recall@5 | Hit@5 | 全部正例完整命中 | MRR@5 | 融合候选物化后的 Recall |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧固定 700 字符 / 三子一父 | 1,350 | 463 | 59.01% | 76.59% | 38.17% | 0.6254 | 86.77% |
| 旧章节 700 字符 / 三子一父 | 3,817 | 3,788 | 64.91% | 84.48% | 41.22% | 0.6126 | 99.58% |
| 新自动识别（全部为结构化） | 13,959 | 3,786 | 61.41% | 81.42% | 37.91% | 0.5725 | 97.47% |
| 新父 1024 / 子 256 tokens | 4,133 | 3,787 | 63.72% | 83.46% | 39.44% | 0.6076 | 99.75% |

Recall@5 为逐题正例完整引文覆盖比例的宏平均，Hit@5 为至少一条正例完整覆盖的问题比例，全部正例完整命中要求该题所有正例均覆盖。一条标注引文必须完整出现在同文档的同一条来源中；忽略空白及大小写，不拼接多条来源计分。最后一列未施加最终 Top5 和 5000 字符预算，只用于定位阶段损失。

## 实际行为与限制

- 自动模式把 38 个 Markdown 分包全部识别为结构化，生成 13,959 个句子/子条目叶子。这是分包输入造成的结构信号，本轮只能评价自动模式的结构化路线，不能证明短文、长文或超长类型的自动分类质量。
- 新自动和 token 方案命中一个子块即可展开真实父块；旧方案继续按至少两个子块及覆盖比例决定合并。父块范围和子块数量均来自当前生产实现。
- Token 子块均不超过 256 tokens，父块分别不超过 2048 / 1024 tokens；所有方案都没有触发嵌入截断。
- 本轮没有修改候选数、上下文预算或切分阈值来追逐分数。实际业务文档、完整语料、启用重排后的质量及最终回答需另外验证。
- 向量复用、并发查询和本地 SQLite 会影响耗时，不能把记录时间当作业务端到端延迟对照。

## 候选多样性诊断

| 方案 | 融合 Top24 中不同父块的平均数量 | 重复父块占用的额外子块位置 |
| --- | ---: | ---: |
| 旧固定 700 字符 | 20.85 | 3.15 |
| 旧章节 700 字符 | 23.42 | 0.58 |
| 新自动结构化 | 15.44 | 8.56 |
| 新 1024/256-token 父子方案 | 22.52 | 1.48 |

新自动方案召回了较多属于同一个父块的句子，24 个子块候选只覆盖约 15.44 个父块，旧章节方案约 23.42 个。新旧章节方案各题最终均返回 5 条来源，且没有触发 5000 字符截断；本批数据的损失不能归因于最终字符预算。结合候选全文覆盖率从 99.58% 降至 97.47%，候选多样性下降是值得优先验证的原因，但本轮同时改变了子块边界和父块展开方式，不能把全部分差归因于单一因素。

后续可分别对照“合并短句至接近 200–256 tokens”和“扩大子块候选后按父块去重/排序”，仍保持同一问题集和固定总上下文预算。本次只报告当前实现，没有按结果调整参数或重新挑选样本。

## 复现与产物

运行 `scripts/evaluate-chunk-profiles.py prepare/encode/evaluate` 三个阶段。prepare 与 evaluate 使用后端 Python 环境；encode 使用具有 CUDA torch、兼容 transformers/tokenizers 的环境，模型文件只读。

独立检索服务复用 `outputs/token-chunking-20261026/compose.yml`，端口 39530。各阶段参数：

```powershell
python scripts/evaluate-chunk-profiles.py prepare --model E:/Code/HUGGINGFACE_CACHE/models--BAAI--bge-m3/snapshots/5617a9f61b028005a4858fdac845db406aefb181 --output outputs/chunk-profiles-20261027
# 同样的 --model / --output 参数，分别执行 encode、evaluate。prepare 要求新的输出目录。
```

`outputs/chunk-profiles-20261027/experiment.json` 固定数据、模型、代码与参数；`*-documents.json` 保存真实分块；`*-cases.jsonl` 保存每题原始双路候选与完整最终来源；`summary.json`、`diagnostics.json`、`verification.json` 为结果、配对统计和独立核验。业务数据库与现有业务索引未改动。
