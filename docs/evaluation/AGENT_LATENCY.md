## 独立查询并行与重复查询复用

- 同批 `knowledge_search` 与 `list_knowledge_bases` 可以一起调度，按原工具调用顺序回填结果。
- 重复查询先等待相同查询的结果，只有实际执行的检索占用并发名额。
- 其他工具仍是批次边界；整批执行前检查每个工具的授权。
- 原有权限检查、文档版本失效、来源撤销和恢复复用逻辑继续生效。

`test_search_parallel_cache.py` 使用事件屏障验证并行：查询 A 必须等到独立查询 B 开始，
重复 A 或目录调用不能挡住 B。另覆盖并发上限 1/2/4、输出顺序、预算结算、失败取消及恢复。
这些测试验证调度行为，没有测量真实知识库或远端工具的提速比例。

## 第四项：耗时与调用指标

管理员 Trace 详情新增 `latency`，前端 Trace 页面显示同一组指标。
复用既有任务、事件和步骤记录，无需数据库迁移，也不增加逐 token 数据库写入。

| 字段 | 口径 |
| --- | --- |
| `queue_ms` | 创建到首次执行；恢复任务取最早已记录执行，不使用最近一次恢复覆盖首轮排队 |
| `first_text_ms` | 创建到首个非空公开 `text_delta` 的持久化时间；隐藏规划、子助手草稿和恢复事件不计入 |
| `total_ms` / `elapsed_ms` | 创建到终态 / 创建到采样时刻；未终态时 `total_ms` 为 null |
| `model_work_ms` / `tool_work_ms` | 已记录模型请求 / 工具调用的累计耗时；包含嵌套和并行，不能相加当作整轮耗时 |
| `model_retries` / `model_corrections` | 网络重试请求数 / 首次执行的格式纠正请求数，格式纠正的网络重试不重复计入纠正数 |
| `reasoning_tokens` / `unknown_reasoning_calls` | 供应商明确报告的思考 token 已知小计 / 未报告的请求数量；未知不填零 |

每个真实 Agent 模型请求的 `details.first_text_ms` 是该请求开始到首次解析出非空文本，
与任务的公开首段正文不同；工具提案、未输出文本的失败请求保留未知。
规划 / 执行 / 反思通过 `details.purpose` 区分。
结构化 RAG 请求现阶段不记录首段文本时间，保留未知。
思考 token 属于供应商输出 token 的明细，不应再加到总输出量中。
两项请求元数据同时进入现有 Langfuse Generation 导出。
以上都不是浏览器实际绘制时间，不包含浏览器端网络和渲染延迟。
