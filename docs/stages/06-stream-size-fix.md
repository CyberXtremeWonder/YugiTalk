# 模型回答中断修复与验收

日期：2026-10-11。更新范围为本地开发环境，不代表正式服务器上线。

## 已查明的情况

截图对应最近失败任务的错误码为 `model_response_too_large`，已保存正文为 928 个 UTF-8 字节、205 次正文增量；单次与累计 Token 额度均关闭。这不是 Token 额度耗尽。执行器正文上限为 64 KiB，因此本次触发的是模型协议适配器的大小检查。

原适配器把所有 SSE 行累计进 256 KiB 容量，同时限制单行长度。协议元数据、非正文增量和可见正文共同消耗此容量，正文很短的碎片流也可能被提前终止。旧日志没有保存容量计数或原始协议帧，无法进一步确定这次是总流容量还是单帧触发；本轮不重新向供应商发送问题或知识库证据。

## 修复

- `MODEL_MAX_STREAM_BYTES` 默认 4194304，即 4 MiB；配置范围为 256 KiB 至 16 MiB。开发和生产模板一致，私有 `.env` 无需改写即可使用默认值。
- 单帧最大 64 KiB，改为按 UTF-8 字节判断；可见正文累计最大 64 KiB；工具参数累计最大 64 KiB。保留执行器跨步骤的正文上限、超时、取消、权限和完整结束校验。
- 整体或单帧协议超限使用 `model_stream_size_limit`；实际正文或工具参数超限仍使用 `model_response_too_large`，Token 输出截断使用 `model_output_limit`。页面分别展示中文原因，不再统一显示未知错误。
- 非正文推理增量不作为答案展示；只展示公开流程与工具状态。
- 新的协议超限日志只记录总流、单帧、配置上限与正文字节数，不记录问题、证据、密钥或模型原文。
- 原失败任务及部分回答保留，不自动重跑、修改成功状态或声称恢复了完整回答。

代码入口：`backend/app/providers/client.py`、`backend/app/core/config.py`、`frontend/src/tasks/errors.ts`。无需数据库迁移。
