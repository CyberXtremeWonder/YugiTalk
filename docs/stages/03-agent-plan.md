## 执行与隔离原则

- API 负责身份、成员权限、私有会话与创建任务；Linux Worker 执行模型和工具，PostgreSQL 保存运行及事件，不依赖 API 进程内存保持状态。
- 模型接入放在独立适配层，领域执行逻辑不绑定供应商 SDK。两个真实协议适配器均做契约测试；具备凭证的供应商另做小规模真实联调。
- 发布 Agent 配置时保存不可变版本；创建运行时记录版本、模型、提示词、工具白名单和限额，修改配置不影响已有运行。
- 工具先实现受控只读工具，参数与结果使用严格 Schema；工具执行前重新检查当前成员权限与配置白名单。知识检索在阶段 4 接入，写工具与人工审批在阶段 5 接入，不能提前以无审批外部写入完成闭环。
- 每次运行使用有界模型步数、工具次数、总时长和 Token 预算。空间／用户／运行并发和预算在 PostgreSQL 事务中预留，并在终态结算，避免多个 Worker 同时超额。
- SSE 用 Cookie 鉴权；每条事件携带运行 ID、事件 ID 和序号，数据库事件持久化、有保留上限，支持 Last-Event-ID 补读。已终止运行不再输出新的有效步骤；事件过期返回 410。
- 普通断网不会取消任务；停止生成是显式修改请求，需要 Origin 与 CSRF。取消完成通过事务竞争确定唯一终态，检查取消状态后再开始新模型或工具调用。
- 队列重复投递不应重复启动同一运行。完整检查点恢复、Worker 宕机接管与审批续跑按阶段 5 验证；不能把 SSE 补读误称为任务执行恢复。

## 真实供应商配置

用户选择真实供应商后，在根目录 `.env` 配置现有字段，不把密钥发到聊天、写入 README、前端或测试产物：

```dotenv
MODEL_PROVIDER=openai_compatible
MODEL_ID=供应商实际支持的模型标识
MODEL_BASE_URL=供应商实际接口地址
MODEL_API_KEY=本地填写的密钥
```

选择 Anthropic 时使用对应 provider 值和实际模型。开发环境没有密钥仍可通过 Mock 启动，但 Mock 测试不替代真实模型验收。真实联调使用短提示、严格步数和 Token 上限，记录脱敏用量；预估成本若没有可核对的价格版本应明确显示不可估算，不伪造费用。

Compose 的 API、Worker 与迁移复用一份后端镜像；模型字段已明确透传。修改根目录 `.env` 后须重新创建 API 与 Worker，并重新发布助手版本；已有运行仍保留原版本快照。
