# 用户私有远程 MCP

## 使用

在侧栏打开独立的“MCP”页面，填写服务器名称、URL 和传输类型。Tool 页面仅管理原有工具：

- `SSE`：传统 HTTP + SSE，通常地址以 `/sse` 结尾。
- `Streamable HTTP`：通常地址以 `/mcp` 结尾；以提供商实际给出的地址为准。

可填写独立 Bearer Token，无认证服务留空。保存后点击“测试连接 / 更新工具”，再勾选要启用的工具；随后到助手或技能配置中授权这些工具。

测试连接仅初始化连接、发现工具，不执行 `tools/call`。新发现或声明发生变化的工具默认停用。删除使用与 Web 界面一致的确认对话框。

修改配置后需重新发现工具；修改 URL 时必须重新输入 Token 或明确清除 Token。留空 Token 表示保留，勾选清除表示删除。Token 永不回显。

## 子代理决策

任务冻结的工具目录中含 MCP 工具时，使用既有 Router → 执行子代理路径，即使问题较简单也不走直接执行路径。

1. 主助手只获得 `delegate_task`，将任务交给执行子代理。
2. 子代理获得本任务授权的工具 Schema，自行判断是否需要 MCP；不需要则直接回答，缺参数时澄清。
3. 子代理提出调用后，后端确定性验证用户、服务器状态、配置版本及参数，再执行。
4. 子代理结果先持久化，主助手根据结果回答。模型判断不能授予或扩大权限。

沿用父任务的预算、超时、租约、追踪、执行账本及恢复机制。远端结果和工具说明都作为不可信资料处理。

## 隔离与凭证

- `account_id` 由登录会话推导，服务器、工具及其 API 仅当前用户可访问；普通用户可管理自己的 MCP，无需平台管理员发布。
- MCP 工具使用服务器 ID 和远端名称摘要生成内部名称，避免不同服务器同名冲突。
- 每次发现或调用使用独立客户端，不共享认证状态、连接或远端会话。
- 凭证独立加密保存，绑定用户和服务器。加密复用现有服务端 `SESSION_SECRET` 机制；API 与 Worker 必须配置同一强密钥，轮换需迁移已有密文。
- 任务快照、工具版本、公开接口和审计不包含 Token 明文或密文。业务工具结果仍按现有工具执行策略落库，不应授权远端返回其他账号的凭证。
- 每次网络操作及公开结果前复核当前权限。停用、删除、修改配置会阻止旧任务继续调用或复用缓存；已发送到远端的副作用无法撤回。
- 删除服务器同时删除保存的凭证，软删除其工具；配置版本及执行历史保留。

## 网络与协议边界

- 仅接受公共 HTTPS、端口 443；拒绝 URL 凭证、查询串、片段、本机及私网目标。需要 URL 查询密钥、自定义认证头或 OAuth 的服务器当前不支持。
- 每次连接校验全部 DNS 解析结果并固定实际连接 IP，保留原域名 TLS 证书校验；不跟随重定向。SSE 返回的 POST 地址必须同源，再次校验网络目标；允许该地址的会话查询串。
- 当前客户端支持初始化协商版本 `2024-11-05`、`2025-03-26`、`2025-06-18`、`2025-11-25`。仅支持新版无初始化协议的服务器会返回不兼容错误。传输选择不代表支持所有协议修订。
- 支持初始化、工具分页发现和工具调用；不开放 stdio、服务器发起的模型采样、文件根目录、资源抓取或交互授权。
- 工具参数支持嵌套 JSON Schema 与本地引用；拒绝外部引用及 `$id`。工具列表最多 100 项、Schema 最多 16 KB、嵌套最多 20 层。
- 每用户最多 10 个有效服务器，工具沿用目录总量限制；每次连接操作总时限 60 秒、单次网络等待最多 10 秒、累计读取最多 1 MiB、最终工具结果最多 16 KB。任务调用并发沿用既有用户任务并发限制。
- 不自动重试 MCP 调用。发送前先持久化执行意图；恢复时若账本结果未确认，则以 `mcp_execution_uncertain` 停止，避免重复外部写入。需要用户在远端确认后再决定后续操作。

## API 与部署

| 方法 | 路径（前缀 `/api/v1`） | 功能 |
| --- | --- | --- |
| GET / POST | `/me/mcp-servers` | 列表 / 创建 |
| PUT | `/me/mcp-servers/{id}` | 保存配置新版本，撤销旧任务配置 |
| PATCH | `/me/mcp-servers/{id}` | 启停 |
| DELETE | `/me/mcp-servers/{id}` | 删除及清除凭证 |
| POST | `/me/mcp-servers/{id}/discover` | 连接并发现工具 |
| PATCH | `/me/tools/{name}` | 启停单个 MCP 工具 |

新增迁移 `0021_mcp`，创建 `mcp_servers`、`mcp_server_versions`、`mcp_credentials`。工具目录、版本和调用账本继续复用现有表。

更新运行环境依赖并应用迁移，再重启 API、Worker、Scheduler 和前端。Compose 部署可使用既有完整更新命令：

```powershell
docker compose up --build -d --wait --wait-timeout 600
```

本机开发环境在 backend 工作目录执行 `python -m alembic upgrade head`，使用该项目的虚拟环境及既有数据库配置。本文不代表真实数据库已应用迁移。

## 验证

`backend/tests/test_mcp.py` 覆盖两种传输的初始化、工具发现和调用、SSE 同源限制、用户隔离、凭证加密、配置变更与停用撤权、执行结果不明时拒绝重发，以及子代理调用/不调用 MCP 的完整任务路径。网络和模型均采用隔离替身，不依赖真实公开服务或发送业务资料。
