# Agent 规划与检查闭环（第一版）

在 Agent 页面勾选“启用规划与检查闭环”，创建助手或发布新版本，然后在对话页选择该版本。旧版本未配置 `closed_loop` 时默认关闭。

执行顺序：Plan → 模型与授权工具循环 → Reflect → 通过后发布答复；检查发现缺口时修订计划并再次执行，最多修正一次。计划最多五步，每步包含行动与完成标准。模型调用上限、工具次数、预算和超时在各阶段共享，不因修订重置。纯文本任务至少需要三次模型调用；包含工具调用和修订的任务需要更多额度。默认六次调用可能在修订前达到上限，可按实际任务调整后发布新版本。真实供应商含重试的保守预算开销更高，启用时建议将预算调至 100000；额度仍不保证任意复杂任务完成。

计划和逐项检查结果通过公开事件在“处理过程”中展示。候选答复和控制 JSON 不进入文本事件或正式消息；通过检查后，答复与终态在同一事务中发布。无法完成或一次修正后仍未满足标准，任务标记失败并说明缺口。取消、预算耗尽或格式无效时不发布草稿。

检查要求覆盖全部计划步骤。需要工具证据的检查必须引用实际成功的工具调用 ID；伪造、失败或缺失的调用不能通过程序校验。语义完整性和是否需要工具仍依赖模型判断，检查通过不代表事实绝对正确。Mock 只用于演示流程，不代表真实质量验收。

计划、候选答复、检查结果、修订次数与累计计数保存在现有检查点中。恢复从阶段或工具游标继续，工具执行沿用原有账本。已保存的工具结果可复用；尚未保存结果的模型请求在恢复时可能重新调用。

本版仅在当前任务内检查和修订，不自动写入长期记忆。RAG 仍在 Agent 循环之前准备证据，闭环不能重新触发检索；证据不足时说明缺口，不使用通用知识替代。知识库无有效证据时沿用现有直接拒答路径。

关键验证：`backend/tests/test_agent_loop.py` 覆盖草稿隔离、一次修订、证据引用、调用上限、各阶段恢复、工具结果复用以及终态消息的幂等发布。真实供应商的结构化输出兼容性、效果、耗时和用量仍需实际联调。
