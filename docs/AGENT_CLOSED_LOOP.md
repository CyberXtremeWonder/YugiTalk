# Agent 规划与检查闭环

更新日期：2026 年 11 月 13 日。配置 `closed_loop` 会随助手版本冻结，旧版本省略时默认关闭。当前有直接执行、Router 委派和兼容前置 RAG 多条入口，不能将开启闭环理解为每个问题都必经相同三步。

## 路由与执行

`tasks/router.py` 为新会话的明确简单问答保留直接路径；`run_direct()` 使用普通模型工具循环，避免不必要的规划和检查。复杂任务等情况由 `run_router()` 委派，子执行助手继承助手的 closed_loop 配置。原普通闭环图与旧任务恢复路径继续保留。

真正进入 `agents/loop.py` 时，顺序是 Plan → 模型与授权工具循环 → Reflect。计划最多五步，包含行动和完成标准；检查缺口时最多一次自动修订。规划、执行和检查共同累计模型步数、时间与预算，不在修订后重置。无工具且不修订时通常也需要三次模型调用；默认六步不保证复杂任务完成。

计划和检查通过公开事件展示，控制 JSON 与候选草稿不作为正式回复；通过后交付结果，无法完成或修订后仍不满足时说明缺口并失败。检查必须覆盖所有计划步骤，需要工具证据的项引用实际成功调用 ID；语义质量仍依赖模型判断，程序通过不等于事实正确。

## 恢复与人工介入

计划、候选、检查、修订计数和消息保存在原 Run 的检查点。已提交工具结果可以复用，未完成的模型请求可能重新调用和计费。历史 `max_tool_calls` 仅保留兼容，当前不以它限制工具次数；模型步数、重复调用、权限、上下文和超时继续限制执行。

主助手插话在模型边界加入 user 消息。如果在准备检查旧候选时合并了新指令，普通闭环流程进入修订；当前委派先完成，父助手随后消费插话。子助手不各自消费父 Run 的指令，详见 [HITL](HITL.md)。

显式知识库兼容路径在 Agent 前准备证据；自动执行助手则可以调用授权 knowledge_search，不能统一表述为闭环永远不能再检索。证据不足的有界回答和来源保护仍然生效，见 [增强 RAG](ENHANCED_RAG.md)。

## 代码与验证入口

`agents/loop.py`、`agents/graph.py`、`agents/subagents.py` 和 `tasks/router.py` 分别负责闭环、模型工具图、委派和冻结路由。测试见 `test_agent_loop.py`、`test_direct_execution.py`、`test_subagents.py`、`test_steering.py`。这些脚本化模型测试验证控制流程，不替代真实供应商效果、结构化协议兼容和用量验收。
