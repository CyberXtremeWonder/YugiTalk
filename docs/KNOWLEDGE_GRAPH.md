# 第一版知识图谱与 RAG 融合

本版保留现有 Dense + BM25、父块合并、重排、评分和原文引用。在查询中额外识别实体，最多扩展两跳，将关系所指向的原文分块与已有候选按 RRF 融合。图谱文本不直接成为答案证据；最终来源仍读取 SQL 原文并复核权限和版本。

## 使用方式

### 可视化面板（2026-11-02）

进入“知识库”，切换“知识图谱”，选择知识库和已完成索引的文档。
面板采用关系筛选、关系网络、实体详情三栏布局；支持实体搜索、1–3 层邻接展开、
节点拖动、画布平移、滚轮和按钮缩放、重置、全屏及实体列表。
整站沿用蓝白色板，并提供相应深色主题和窄屏布局。

界面使用现有 `/documents/{id}/graph` 接口。当前按文档查看，最多显示已返回的前 100 条关系，
不将不同文档的同名实体自动合并。接口未提供实体分类，因此按真实关系类型筛选，
节点颜色仅用于视觉区分。统计分别标明接口实体总数和当前已显示的实体、关系数量。

点击节点可查看关联关系、连续原文引文及分块身份；点击“查看原文”会重新请求
`/sources/{chunk_id}?index_version=...`，不将图谱摘要冒充原文。
已删除、更新或无权访问时清空原文预览并显示明确提示；切换文档时重建面板状态。
图谱未构建、正在构建、失败和无关系时显示相应状态，保留原有构建与重建入口。

验证：70 项前端测试、31 项后端图谱测试通过，TypeScript、ESLint 和生产构建通过。
`node scripts/check-graph-explorer-ui.mjs` 使用隔离 API 数据验证节点选择、版本化原文读取、
来源撤销、搜索、筛选、拖动、缩放、全屏、文档切换、深浅主题及窄屏；
截图写入 `frontend/.cache/knowledge-graph-ui/`。这不代表已在生产知识库上验证抽取质量。

### 文档导入与构建

知识库支持 TXT、Markdown、PDF、Excel（`.xlsx`、`.xls`）、Word（`.docx`、`.doc`）及 PNG、JPEG、TIFF、BMP、WebP 图片。PDF、Office 和图片统一由本机 Docling 服务转换为保留表格结构的 Markdown，并启用 OCR；TXT、Markdown 直接读取。所有格式共用原文分块、检索与图谱流程，图片 OCR 的文字也可参与图谱；当前不默认启用插图的视觉语义描述。旧版 Office 在 Docling 容器内通过 LibreOffice 转换，不再使用 antiword 或单独的 Excel/Word 解析器。

启动解析服务：`docker compose up -d --build docling`。首次需下载固定摘要的官方 CPU 镜像及模型，容器内存上限为 6 GB，端口仅绑定 `127.0.0.1:18082`。Worker 的 `DOCLING_URL` 在 Compose 中为 `http://docling:5001`，独立运行时默认 `http://127.0.0.1:18082`。生产覆盖文件移除宿主端口并使用私有网络。解析服务禁止远程模型调用；服务不可用、超时或只返回部分结果时，导入明确失败，不静默回退旧解析器。

更新已有服务时重新构建并更新 API、Worker 和前端。既有文件保持原索引；需点击“重新索引”才会按 Docling 重新解析并重建图谱。单文件最多 20 MB、提取文本最多 500 万字符、最多 6 万个子块及 PDF 最多 2000 页；完整资源边界见 [文档分块](DOCUMENT_CHUNKING.md)。Docling 转换窗口为 600 秒，独立解析进程上限为 650 秒。

1. 更新数据库至 `0017_knowledge_graph`，更新 API、Worker、Scheduler 和前端。必须先迁移再启动新版本服务。
2. `RAG_GRAPH_ENABLED=true` 默认启用。新文件普通索引完成后，后台自动登记图谱构建任务，Scheduler 负责投递。
3. 知识库文件下展开“知识图谱与原文依据”，可查看构建状态、实体数量、关系和连续原文片段。
4. 已有文件不会自动批量补建。点击“构建图谱”或“重新构建图谱”，不重新调用 Embedding、不增加文档索引版本。
5. 按原来的方式选择知识库提问。图谱有结果时参与召回；未构建、构建失败或关闭功能时继续使用普通 RAG。

真实抽取复用 `RAG_FAST_MODEL`，未配置时使用默认聊天模型及当前供应商凭证。会增加模型调用和费用。Mock 模式只验证任务流程，明确显示演示模式，不伪造实体和关系。切换真实模型后需重新构建演示图谱。

按现有部署流程执行迁移，例如在已配置数据库的后端目录执行：

```powershell
.venv/Scripts/python.exe -m alembic upgrade head
```

Docker 部署继续使用现有 migrate 服务，并更新 api、worker、scheduler、frontend。该说明不表示本轮已迁移业务库或重启服务。

## 数据与可靠性

- `graph_builds`：文档代次、独立构建状态、模式、失败原因、执行令牌、租约和投递时间。
- `graph_entities`：文档内名称、类型和明确别名。不同文档实体保持独立；同名同类型仅用于扩展候选，不宣布身份相同。
- `graph_facts`：一条关系的一份原文依据，包含两端实体、分块、引文和文档版本。多文档可分别支持同一关系；删除一个文档不影响其他文档的依据。

抽取结果必须通过结构校验；名称、别名必须出现于原文，关系引文必须是连续原文且包含双方名称或别名。无法核验的实体及关联关系逐条剔除，其余有效结果继续构建；模型服务或结构校验错误仍会使构建失败。该校验保证来源可定位，不能证明模型对关系语义的理解一定正确，仍需质量评测。

原文索引发布与图谱排队意图在同一事务提交。图谱抽取结束后在文档锁下再次校验状态、版本和令牌，并一次性发布。半成品不参与检索。每次模型调用及读取期间检查文档与账号状态。删除、重新索引、旧令牌失效均阻止旧构建发布。

调度器每次最多扫描 100 个待处理任务，30 秒后可补投；每批执行窗口 180 秒、租约 200 秒。成功批次持久化结果并投递下一批，队列故障由调度器补投。失联批次、模型暂时不可用或网络超时最多领取 3 次，恢复时跳过已完成的分块；鉴权或结构校验失败需手动重建。重复队列消息不重复构建已领取任务。

图谱查询异常在 SQL 保存点内回退，流程记录 `graph_candidates=-1`；后续原文授权校验不会被吞掉。关闭功能不会删除已有图谱。

## 首版边界

- 大文档按每批最多 4 个分块处理，页面显示已处理分块数。所有批次完成并校验成功后才发布整份图谱；中间结果不参与检索。删除或重新索引会清理暂存结果。
- 每块发布最多 12 个实体、12 条关系，模型输出最多 4096 Token。解析可容纳最多 64 项候选，再按原文校验并限制发布数量；名称允许有原文依据的单字实体。模型超时、结构输出错误不会伪装成抽取成功。
- 实体类型：人员、组织、系统、产品、概念。关系：负责、属于、依赖、使用、关联。
- 查询实体名称与明确别名采用文本匹配，未加入实体向量检索、模糊消歧、社区摘要或任意深度路径搜索。
- 召回最多读取 10000 个有效候选实体；超过则跳过图谱召回。最多 8 个种子、每跳最多 32 个节点、每节点最多 8 条关系，最多两跳，受现有总候选数限制。
- 原有最终 5 条来源和上下文长度限制保持不变。复杂路径可能因候选截断或重排缺失部分依据；不能保证完整多跳推理，仍由原文评分决定能否回答。
- 页面最多展示 100 条关系依据，明确提示还有更多。

## 接口与代码

- `GET /api/v1/documents/{id}/graph`：按文档权限读取状态和原文关系。
- `POST /api/v1/documents/{id}/graph`：需要登录、写权限和 CSRF 校验，登记补建或重建任务。
- `backend/app/rag/graph.py`：抽取、发布、恢复、实体匹配、两跳召回和融合。
- `backend/app/rag/graph_models.py`：图谱数据实体。
- `backend/app/rag/pipeline.py`、`indexing.py`：聊天及直接检索接入。
- `frontend/src/rag/GraphPanel.tsx`：状态与原文关系查看入口。
