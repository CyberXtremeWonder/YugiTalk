# ADR 0006：独立生产环境与跨存储冷备

日期：2026-10-10。状态：已实现，阶段6上线门槛未全部通过。

生产覆盖文件明确清空开发端口与源码构建配置，使用 HTTPS 同源入口。业务和监控数据放项目 `data/production/`，与开发挂载隔离；BGE 缓存继续使用用户已有路径。内部服务不映射公网端口，Milvus/Redis启用独立认证，模型密钥仅存在后端受控环境。

选用 Prometheus 与手工 OpenTelemetry 追踪。模板路由限制指标基数，异常只记录类型；业务正文不进入指标、追踪和异常详情。单机 Jaeger Badger 避免额外搜索集群，但不适用于多机高可用。

PostgreSQL、Milvus/etcd/对象存储共同描述知识库，不能分别任意时间热拷贝。首版先停止写入完成冷备，逐文件校验后在独立目录恢复并检查业务指纹。代价是维护窗口和同机备份无法覆盖主机丢失，后续需要受控异机加密副本及调度。

发布以实际镜像 ID 固定版本，备份后的启动也恢复停机前 ID，避免可变标签使备份顺带升级。仅在同一兼容 Schema 内回退镜像，禁止自动降级数据库；迁移变更另行演练。

基础层扫描和运行依赖扫描分开报告。即使依赖无已知漏洞，旧 Python/Nginx 基础层仍可能有严重漏洞。发布门槛以实际扫描为准，不隐藏未修复项目或把隔离测试当作正式服务器验证。

用户确认正式对象存储采用现有服务器/云端S3。开发MinIO数据保留，正式默认不启动旧MinIO；两个预置Bucket分别承载原文和Milvus对象。S3配置及本地协议接入已验证，真实服务暂缺。跨存储冷备脚本仅适用于本地对象存储，外部S3发布在停机前拒绝，待补齐对象版本/快照与真实恢复演练。远端对象明确成为项目目录持久化要求的例外，BGE模型缓存也按原约定保留。
