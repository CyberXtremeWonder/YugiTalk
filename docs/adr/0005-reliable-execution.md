# ADR 0005：应用检查点、租约及工具执行账本

日期：2026-10-10。阶段：5。范围修订：用户要求工单创建在项目全部完成后再拓展。

## 决策

PostgreSQL 保存排队意图、图边界、工具游标、流式事件与执行账本。Redis/Celery 允许至少一次投递；独立 Scheduler 定期补投排队任务与回收失效租约。API、Worker、Scheduler 共享后端镜像，使用独立启动模式。

LangGraph 负责有界模型与工具节点循环。应用在模型节点边界及每个工具完成后保存 JSON 检查点，恢复时明确选择模型或工具入口。这不是直接启用 LangGraph 原生 checkpointer；由应用统一校验权限、租约、预算与参数，避免框架状态与业务账本各自提交而发生歧义。检查点含上下文，只允许服务端读取。

Worker 持有随机租约令牌，HTTP 阻塞期间由独立线程续租。每次状态写入、工具执行、终态结算均检查令牌与到期时间；过期令牌不能复活。恢复领取生成新令牌，防止旧 Worker 的晚到结果覆盖新任务。互斥依赖 PostgreSQL 行锁及令牌校验。

只读工具结果保存至 ToolExecution，唯一约束绑定运行与调用键，参数哈希防止错配。若结果提交后、图检查点保存前宕机，恢复查询账本复用结果，不再次执行已完成工具。真实 PostgreSQL 并发测试验证重复投递只产生一条执行记录与一条答复。

## 范围调整与数据兼容

移除 create_ticket 注册、Mock 提案、授权选项、工单列表、审批卡和审批/工单业务接口。新配置拒绝下线工具；旧助手配置在响应和运行时过滤，发布版本和旧运行快照保持不可变。执行边界再次拒绝下线工具，不能复用其旧结果。旧 waiting_approval 任务统一结束并释放预算。

既有迁移和 Approval、Ticket 表映射保留，以免删除用户历史数据；它们不代表当前可用功能。工单及写操作审批在全部阶段完成后另行设计、实现和验收。

## 取舍

- 完整模型响应提交前宕机，可能再次调用模型并增加费用；额度继续累计，前端替换未提交片段。
- 文档恢复从原文重建并增加索引版本，避免旧 Worker 发布半成品；重复编码有成本。
- 自动恢复有次数上限；可恢复模型故障允许用户带新幂等键确认重试，旧费用只结算一次。
- 只读工具账本验证不等于外部写入保证。后续写工具必须增加具体参数审批、稳定幂等键与结果对账，未知结果不能直接重放。
- 生产发布、HTTPS、监控告警、恢复时间目标与保留策略继续在阶段 6–7 验收。
